Tom-eyes only. Run end-to-end after `T11.8.7` lands and before `git push origin main`.

The goal: prove Sparkle 2 + EdDSA verification + the relaunch gate work end-to-end against a real R2-hosted zip and a real Pages-hosted appcast — without polluting the prod feed at `https://updates.taproothq.com/appcast.xml`.

- `wrangler` authed as `tomjrworks@gmail.com` (`wrangler whoami`).
- R2 bucket `taproot-releases` reachable at `https://downloads.taproothq.com` (public-READ).
- Pages project `taproot-updates` connected to `https://updates.taproothq.com`.
- Sparkle EdDSA private key in Keychain (`https://sparkle-project.org` / `ed25519`) and Apple Passwords backup.
- Apple Developer ID Application certificate `BC24E4A647583D1B567D8A0CD3DFBE74C3A2C522` installed in login Keychain.

## 1. Prep

Helper running at `0.1.0` (current `CFBundleShortVersionString` per `Sources/TaprootHelper/Info.plist`). Either live HEAD or an installed `.app` is fine — what matters is the running binary reports `0.1.0` in Settings → Version.

Confirm:

```bash
defaults read com.taproot.helper SUHasLaunchedBefore   # should be 1
```

## 2. Build staging 0.1.1

In a temporary branch (do NOT commit version bumps to `main` until after smoke passes):

1. `Sources/TaprootHelper/Info.plist`: bump `CFBundleShortVersionString` → `0.1.1`, `CFBundleVersion` → `2`.
2. `swift build -c release` from `helper-mac/`.
3. Wrap into `.app` via the existing build path.
4. Codesign:
   ```bash
   codesign -s "BC24E4A647583D1B567D8A0CD3DFBE74C3A2C522" --options runtime TaprootHelper.app
   ```
5. Zip:
   ```bash
   ditto -c -k --sequenceNumber --keepParent TaprootHelper.app TaprootHelper-0.1.1.zip
   ```

## 3. Sign for Sparkle

Use the binary path corrected in the F1 prep finding — Sparkle's CLIs live in the SwiftPM artifacts `bin/` dir, NOT inside the framework `Resources/`:

```bash
./.build/artifacts/sparkle/Sparkle/bin/sign_update TaprootHelper-0.1.1.zip
```

Capture the printed `sparkle:edSignature="..."` and `length="..."`. `sign-and-publish.sh` parses these automatically — running it directly is the recommended path:

```bash
./scripts/release/sign-and-publish.sh 0.1.1 2 ./TaprootHelper-0.1.1.zip
```

That writes `scripts/release/out/appcast-0.1.1.xml` and prints the wrangler commands for the next step.

## 4. Publish staging artifacts

Run the wrangler commands `sign-and-publish.sh` printed (it does NOT execute them — operationally safer):

```bash
# 1. Upload signed zip to R2
wrangler r2 object put taproot-releases/releases/v0.1.1/TaprootHelper-0.1.1.zip \
  --file=./TaprootHelper-0.1.1.zip \
  --content-type=application/octet-stream

# 2. Deploy appcast to a Pages preview (staging)
wrangler pages deploy ./scripts/release/out --project-name=taproot-updates
```

Wrangler emits a per-deploy preview URL like `https://<commit>.taproot-updates.pages.dev/appcast.xml`. **Copy that URL** — it's your staging feed for step 5. The `taproot-updates-staging.pages.dev` static slug from the original parent plan does not exist; preview URLs are per-deploy only.

## 5. Point running 0.1.0 at staging

```bash
# Quit helper first (cmd-Q from menubar, or `pkill TaprootHelper`)
defaults write com.taproot.helper SUFeedURL "https://<preview-host>/appcast.xml"
# Reopen helper
open /Applications/TaprootHelper.app   # or wherever your installed .app lives
```

## 6. Trigger check

Wait the ~10s startup delay for Sparkle's first scheduled check, OR click Settings → Check for updates.

## 7. Acceptance assertions

- [ ] Sparkle dialog appears: "A new version of Taproot is available. Taproot 0.1.1 is now available — you have 0.1.0."
- [ ] Release notes from `<description>` render in the dialog (the `<p>Auto-update support (T11.8).</p>` default, or whatever was passed via `--release-notes`).
- [ ] Click **Install Update**. Progress bar shows. Download completes.
- [ ] EdDSA verification passes silently — **no signature-error dialog** (this is the M15 + commit-7 pubkey paste paying off).
- [ ] Sparkle prompts "Ready to install" → click **Install and Relaunch**.
- [ ] Helper terminates and relaunches.
- [ ] Settings → Version row reads `0.1.1`.
- [ ] No Sparkle-related crash logs in `~/Library/Logs/DiagnosticReports/`.

## 8. Edge-case smokes

### 8a. Silent auto-install (still respects relaunch gate)

```bash
defaults write com.taproot.helper SUAutomaticallyUpdate -bool YES
```

Quit + relaunch helper. Trigger another update (re-publish a staging 0.1.2 via steps 2–4, or just re-deploy with a fresh preview URL). Confirm:

- [ ] Install runs without confirmation dialog.
- [ ] Relaunch still respects `shouldPostponeRelaunchForUpdate` — if a push is in flight at that moment, helper waits for it.

### 8b. Push-in-flight relaunch postpone (V4 hook + V3 atomic counter)

While the update download nears completion, touch a file in a watched workspace folder so SyncEngine's `pushInFlight` counter goes > 0:

```bash
touch ~/path/to/watched/vault/some-note.md
```

Confirm:

- [ ] Sparkle's "Install and Relaunch" is delayed until the push completes (counter returns to 0).
- [ ] If push hangs, the 60s fall-through fires. `Console.app` filter on `process == TaprootHelper` and search `update relaunch:` — you should see:
  ```
  [Taproot] update relaunch: 60s fall-through; isBusy=true; pushInFlight=N; firstRunWindowOpen=false; allowing relaunch despite veto
  ```
  (The `isBusy=...; pushInFlight=N; firstRunWindowOpen=...` segment is the C2 diagnostic telemetry added in commit 7. If it's missing, the snapshot wiring in `AppDelegate.swift:242` regressed.)

## 9. Rollback test

Delete the 0.1.1 entry from the staging appcast (just remove the `<item>` block from the deployed appcast and redeploy, or roll the Pages deployment back), then run cleanup:

```bash
./scripts/release/T11.8-smoke-cleanup.sh
```

Confirm:

- [ ] `defaults read com.taproot.helper SUFeedURL` → does not exist (helper falls back to `Info.plist` default).
- [ ] `defaults read com.taproot.helper SUSkippedVersion` → does not exist (we accepted, didn't skip).
- [ ] `defaults read com.taproot.helper SUAutomaticallyUpdate` → does not exist.

## 10. Promote to prod

ONLY after every assertion in steps 7–9 passes:

```bash
# Re-deploy the SAME appcast to the prod branch
wrangler pages deploy ./scripts/release/out \
  --project-name=taproot-updates \
  --branch=main
```

This points `https://updates.taproothq.com/appcast.xml` at the new appcast. Confirm:

- [ ] `curl -s https://updates.taproothq.com/appcast.xml | head -20` shows the new `<item>` with `0.1.1`.
- [ ] One last `defaults delete com.taproot.helper SUFeedURL` to make sure the helper's prod check hits the prod feed (no leftover staging override).

After prod is live: bump `Info.plist` versions back on `main` (`0.1.1` / `2`), commit as the version bump that ships, then `git push origin main`.

## Aborted-smoke recovery

If anything goes sideways mid-smoke:

```bash
./scripts/release/T11.8-smoke-cleanup.sh   # wipes UserDefaults overrides
# Optionally: pkill TaprootHelper && open /Applications/TaprootHelper.app
```

Helper will re-launch reading `Info.plist` defaults (prod feed URL). The staging zip in R2 is harmless — it's not referenced by the prod appcast. Leave it for the next smoke or `wrangler r2 object delete` if you want a clean slate.
